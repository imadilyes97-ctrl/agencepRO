# MODULE 10 : Notifications & Communication

## 10.1 Vue d'ensemble

Le module de notifications est le systeme nerveux central d'Agence Pro. Il gere toutes les communications sortantes et entrantes entre l'agence, ses clients et ses partenaires, via quatre canaux unifies dans une interface unique.

### Principes directeurs

- **Unifie** : tous les canaux (WhatsApp, Email, SMS, Push) sont geres depuis un seul tableau de bord
- **Bilingue** : chaque template existe en francais et en arabe, avec detection automatique de la langue du destinataire
- **Reglementaire** : conformite RGPD, regles Meta Business, reglementation algerienne sur les communications commerciales
- **Intelligent** : routage automatique vers le meilleur canal selon le contexte et les preferences du destinataire
- **Traable** : chaque envoi est logge avec statut de livraison, ouverture et reponse

### Architecture des canaux

```
┌─────────────────────────────────────────────────────┐
│                MOTEUR DE NOTIFICATIONS               │
│  ┌───────────┐ ┌──────────┐ ┌──────┐ ┌───────────┐ │
│  │ WhatsApp  │ │  Email   │ │ SMS  │ │ Push      │ │
│  │ Business  │ │ (Resend) │ │(SMS) │ │(Firebase) │ │
│  │ API       │ │          │ │      │ │           │ │
│  └─────┬─────┘ └────┬─────┘ └──┬───┘ └─────┬─────┘ │
│        └─────────────┼─────────┼───────────┘        │
│                      ▼         ▼                     │
│           ┌──────────────────────────┐              │
│           │   File d'attente unifiee │              │
```

### 10.2.3 Envoi groupe

**Fonctionnalite :** envoyer le meme message a plusieurs contacts en une seule operation.

- **Selection des destinataires :**
  - Par liste (ex: "Tous les clients Omra Ramadan 2024")
  - Par statut de dossier (ex: "Dossiers en attente de paiement")
  - Par date de voyage (ex: "Clients partant cette semaine")
  - Selection manuelle (checkboxes)

- **Limites techniques :**
  - Max 256 messages par envoi groupe (pour eviter le flag spam)
  - Delai de 100ms entre chaque envoi (rate limiting)
  - Un seul envoi groupe en parallele par agence
  - Compteur visible : "12/256 envoyes..."

- **Controles :**
  - Preview du message avant envoi
  - Confirmation obligatoire ("Confirmer l'envoi a X destinataires ?")
  - Annulation possible tant que pas 100% envoye
  - Option "Envoyer en mode test" (un seul destinataire)

- **Anti-spam :**
  - Detection automatique si le meme template est envoye plus de 3 fois au meme client en 7 jours
  - Blocage automatique + alerte admin
  - Respect des preferences de notification du client

### 10.2.5 Chatbot IA WhatsApp

**Fonctionnalite :** reponses automatiques intelligentes aux questions frequentes.

**Mode de fonctionnement :**
1. Le client envoie un message
2. L'IA analyse l'intention
3. Si la reponse est dans le repertoire (confiance > 80%) : reponse automatique
4. Si la reponse est incertaine (confiance 50-80%) : reponse proposee a l'agent pour validation
5. Si hors repertoire (confiance < 50%) : notification a l'agent + message "Un agent va vous repondre bientot"

**Questions reconnues (minimum) :**

| Categorie | Exemples de questions |
|-----------|----------------------|
| Statut dossier | "Ou en est mon dossier ?", "Mon visa est-il pret ?" |
| Paiement | "Combien dois-je encore payer ?", "Comment payer ?" |
| Documents | "Quels documents sont necessaires ?", "Ou envoyer mon passeport ?" |
| Vol | "Quelle est mon heure de vol ?", "Mon vol est-il confirme ?" |
| Contact | "Comment contacter l'agence ?", "Vos horaires d'ouverture ?" |
| Omra/Hajj | "Quand part la prochaine Omra ?", "C'est quoi le programme ?" |

**Fonctionnalites IA :**
- Acces aux donnees du dossier client (contexte personnalise)
- Multilingue (FR/AR automatique selon la langue du message)
- Historique de la conversation pris en compte
- Escalade intelligente vers un agent humain quand necessaire
- Apprentissage des nouvelles questions frequentes (proposition a l'admin)

**Limite :**
- L'IA ne peut JAMAIS prendre de decisions financieres ou contractuelles
- L'IA ne peut JAMAIS modifier un dossier
- L'IA signale toujours quand elle ne sait pas ("Je ne suis pas sur, je transfere a un conseiller")

### 10.2.6 Session WhatsApp 24h

**Regle Meta :** apres le dernier message d'un client, l'agence a 24 heures pour repondre sans utiliser de template payant. Passes ces 24h, seuls les templates approuves peuvent etre utilises.

**Gestion dans Agence Pro :**

- **Horloge visible** : pour chaque conversation, afficher le temps restant avant expiration
- **Alertes automatiques :**
  - A 4h de l'expiration : notification a l'agent assigne
  - A 1h de l'expiration : notification urgente + alerte admin
  - A expiration : bascule en mode "template uniquement"
- **Actions automatiques :**
  - Si pas de reponse en 20h : propose un message rapide a l'agent
  - Si conversation inactive depuis 23h : envoie un message de relance (template approuve)
- **Tableau de bord session :**
  - Nombre de sessions actives
  - Sessions expirant aujourd'hui
  - Sessions expirees non reprises

## 10.3 Email

### 10.3.1 Configuration technique

- **Provider** : Resend (API REST, deliverabilite superieure)
- **Domaine** : SPF, DKIM, DMARC configures sur le domaine de l'agence
- **Expediteur** : `noreply@agencepro.dz` (transactionnel) / `contact@{agence}.dz` (marketing)
- **Rate limiting** : max 10 emails/seconde par domaine
- **Bounce handling** : suppression automatique des adresses hard-bounce
- **Unsubscribe** : lien de desinscription obligatoire dans chaque email marketing

### 10.3.4 Suivi ouverture et clic

Pour chaque email envoye :
- **Open tracking** : pixel invisible, timestamp de l'ouverture, nombre d'ouvertures
- **Click tracking** : clic sur chaque lien, URL cliquee, timestamp
- **Bounce** : hard bounce (adresse invalide) vs soft bounce (temporaire)
- **Complaint** : signalment spam (delistement automatique)
- **Vue agregatee** dans le dashboard : taux d'ouverture moyen, taux de clic, meilleurs horaires d'envoi

## 10.4 SMS

### 10.4.1 Configuration technique

- **Provider** : Twilio ou operateur local algerien (Djezzy, Ooredoo, Mobilis)
- **Format** : messages courts (160 caracteres max pour SMS simple, 70 pour Unicode/Arabe)
- **Sender ID** : nom de l'agence (si supporte par l'operateur) ou numero dedie
- **Conformite** : respect des regles de l'ARPCE (autorite de regulation)

### 10.4.2 Types de SMS

| Type | Usage | Priorite | Cout |
|------|-------|----------|------|
| **OTP (2FA)** | Code de verification pour connexion | Haute | SMS transactionnel |
| **Confirmation** | Confirmation reservation, paiement | Haute | SMS transactionnel |
| **Rappel** | Rappel paiement, documents, echeance | Moyenne | SMS transactionnel |
| **Urgence** | Alerte vol annule, visa refuse, document expire | Critique | SMS transactionnel |
| **Marketing** | Offre speciale, promotion | Basse | SMS commercial |

### 10.4.3 Templates SMS

**OTP :**
```
Agence Pro: Votre code de verification est {{code}}. Valable 5 minutes. Ne partagez ce code avec personne.
```

**Confirmation paiement :**
```
Agence Pro: Paiement de {{montant}} DA recu pour le dossier {{ref}}. Solde restant: {{reste}} DA. Merci!
```

**Rappel paiement :**
```
Agence Pro: Rappel — Paiement de {{montant}} DA en attente pour {{ref}}. Echeance: {{date}}. Contactez-nous si besoin.
```

**Alerte urgence :**
```
URGENT Agence Pro: {{message}}. Contactez votre agence immediatement au {{tel}}.
```

## 10.5 Push Notifications (Mobile — Phase 3)

### 10.5.1 Configuration technique

- **Provider** : Firebase Cloud Messaging (FCM)
- **Plateformes** : Android (prioritaire), iOS (Phase 3+)
- **Registration** : a l'inscription ou a la premiere ouverture de l'app
- **Preferences** : le client peut activer/desactiver par type de notification

### 10.5.2 Types de notifications push

| Type | Titre (FR) | Corps (FR) | Action au tap |
|------|------------|------------|---------------|
| **Nouveau dossier** | Nouvelle demande | Un nouveau dossier vous a ete assigne | Ouvre le dossier |

Le destinataire peut configurer :
- Activer / desactiver chaque type de notification
- Choisir les canaux (push, email, SMS, WhatsApp)
- Mode "Ne pas deranger" (horaires)
- Frequence maximale (ex: max 1 resume par jour)

4. **Heures de silence** : pas de SMS/Push entre 22h et 8h (sauf urgence critique)
5. **De-duplication** : meme evenement, meme destinataire, meme canal = max 1 fois / 4h

# MODULE 12 : Portail Client (Self-Service)

## 12.1 Vue d'ensemble

Le Portail Client est l'interface web dediee aux voyageurs (clients finaux). Il leur permet de suivre leur dossier, telecharger leurs documents, effectuer des paiements et communiquer avec leur agence — 24h/24, depuis leur telephone ou leur ordinateur.

### Principes directeurs

- **Simple** : interface intuitive, pas de formation necessaire
- **Mobile-first** : concu d'abord pour le telephone, adapte a l'ordinateur
- **Rassurant** : le client sait toujours ou en est son dossier, sans appeler
- **Bilingue** : FR/AR avec detection automatique de la langue
- **Securise** : authentification robuste, donnees chiffrees, conformite RGPD

### Cible

- Voyageurs individuels
- Voyageurs en groupe (Omra, Hajj)
- Accompagnants (via lien de partage)

---

## 12.2 Authentification

### 12.2.1 Methodes de connexion

| Methode | Description | Priorite |
|---------|-------------|----------|
| **Email + mot de passe** | Methode classique | Phase 1 |
| **Lien magique (magic link)** | Email avec lien de connexion (pas de mot de passe) | Phase 1 |
| **OTP par SMS** | Code envoye par SMS | Phase 1 |
| **Connexion sociale** | Google, Apple (Phase 3) | Phase 3 |

### 12.2.2 Inscription

**Etape 1 : Formulaire**
- Prenom et nom
- Email
- Telephone (+213)
- Mot de passe (8+ caracteres, 1 majuscule, 1 chiffre, 1 special)
- Accepter les CGU

**Etape 2 : Verification**
- Email de verification (lien magique)
- OU code OTP par SMS au +213...

**Etape 3 : Profil complet**
- Date de naissance
- Nationalite (defaut : Algerienne)
- Numero de passeport
- Photo (optionnel)

### 12.2.3 Securite

- Tentatives de connexion limitees (5 max, puis lock 15min)
- 2FA optionnel (SMS OTP)
- Session expiree apres 30 jours d'inactivite
- Deconnexion a la demande
- Historique des connexions visible
- Mot de passe oublie : reinitialisation par email
- Detection de connexion suspecte (nouvel appareil, nouvelle IP)

## 12.10 Signature electronique des contrats

### 12.10.1 Processus

1. L'agence genere le contrat (PDF) et l'envoie via le portail
2. Le client recoit une notification : "Nouveau contrat a signer"
3. Le client ouvre le contrat dans le portail
4. Il lit le document (scroll obligatoire pour eviter le signe sans lire)
5. Il clique sur "Signer"
6. Il dessine sa signature sur l'ecran (ou importe une image de signature)
7. Il confirme avec son mot de passe
8. Le contrat est signe horodate, clessee et archivage
9. Les deux parties recoivent le contrat signe par email
10. Le statut du dossier passe a "Contrat signe"

### 12.10.2 Securite de la signature

- **Horodatage** : date et heure exactes de la signature
- **Cle** : chaque signature a un hash unique (SHA-256)
- **Verification** : le contrat signe peut etre verifie via un lien public
- **Non-repudiation** : le client ne peut pas nier avoir signe (hash + IP + horodatage)
- **Archivage** : les contrats signes sont stockes separement avec backup

## 12.11 Partage du dossier (lien public)

### 12.11.1 Cas d'usage

Un voyageur en groupe (Omra/Hajj) veut partager les informations de son dossier avec un membre de la famille qui l'accompagne ou qui veut suivre son voyage.

### 12.11.2 Fonctionnalite

Le client peut generer un **lien public** avec les informations suivantes :

**Visible par le lien public :**
- Prenom et nom du voyageur
- Dates de voyage
- Destination
- Numero de vol (si confirme)
- Statut general du dossier (en cours, pret, etc.)

**NON visible (confidentiel) :**
- Numero de passeport

- **Duree de validite** : 7 jours, 30 jours, jusqu'au retour du voyage
- **Desactiver** a tout moment
- **Mot de passe** optionnel (le destinataire doit entrer un code)

## 12.12 Design et UX du portail client

### 12.12.1 Principes de design

- **Oriente mobile** : 80% des utilisateurs accedent depuis leur telephone
- **Rassurant** : le client doit se sentir en confiance (pas d'angoisse, clarte absolue)
- **Clair** : pas de jargon technique, pas de surcharge d'information
- **Accessible** : respect WCAG 2.1 AA, contraste sufficient, tailles de texte lisibles
- **Bilingue** : pas de troncation FR dans la version AR et inversement

### 12.12.2 Navigation

